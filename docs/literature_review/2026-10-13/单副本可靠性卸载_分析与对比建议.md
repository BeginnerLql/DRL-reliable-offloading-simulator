# 单副本可靠性卸载：249条Zotero文献筛选

> 参数快照说明：本文引用的仓库基础故障率0.001～0.005 s⁻¹及对应算例属于调整前版本。当前配置已改为0.1～0.5 s⁻¹，状态尺度为0.5 s⁻¹，β仍为0.5；历史文献核对和原算例保留。


核查日期：2026-10-13。建议首先选 **RASOUL、TRO、QoE/Reliability-Aware Scheduling、LeDRL** 作为故障可靠性单节点方法的候选。其中RASOUL最接近当前repo的指数执行可靠性，TRO最接近到达驱动、队列与单节点决策；其余方法需要更多系统机制。四篇均有可读本地PDF，具体模型依据如下。

## 覆盖范围与“单副本”的判据

本次从正在使用的Zotero文库SQLite及WAL的只读副本取得249条非删除文献记录；原数据库未修改。177条有实际存在且可提取文本的PDF，69条PDF路径缺失，3条无PDF附件。这里“可读”是解析正文成功，不等于逐一在Zotero界面打开。249条是记录数，重复DOI条目不计作不同算法，例如RTPO的KVZXU9ZL和46CQT2SF。

逐条核对题名、摘要与既有模型筛选记录；对相关候选进一步核读本地系统模型。72条无可读本地PDF的记录均按完整题名逐篇网页检索；相关条目找到系统模型则据模型判断，否则回退摘要。不是把177篇PDF都列作单副本候选，也不声称所有网页检索都找到了全文。逐条证据层级、排除理由和摘要见CSV。

严格单副本指：**一个完整、不可再分的任务选择一个最终计算节点，不另外配置复制/主备执行。** 不同任务分给不同节点、同一任务在计算前多跳转发，仍可以是单副本。任务按比例在多个节点计算、主备副本、并行冗余不属于此类。单点放置但失败后重执行/checkpoint恢复单独列为C类；它可以没有同时活跃副本，却与一次执行模型不同。

可靠性也分三种：CPU/链路故障生存概率；期限/队列溢出/通信服务成功概率；信誉、安全或时延波动风险。下面只有A类可直接讨论与repo故障可靠性表达式的接近程度。

## 当前repo与比较边界

依据本次读取的config/configuration.py、config/params.py和core/main_loop.py：8个异构固定服务器，200个独立任务，Poisson到达率0.5任务/s；输入5–10 MB，CPU需求2–4×10⁹ cycles，处理频率1–4 GHz，传输率5–20 MB/s。服务器单容量队列，当前相同优先级表现为FIFO。

当前每个任务固定选择两个不同服务器，28个无序节点对动作；状态维数5N+2=42。单节点CPU可靠性为Rⱼ=exp(-λⱼ,eff C/fⱼ)，双副本按1-(1-R₁)(1-R₂)记录。每episode采样准静态空间风险场改变有效故障率；配置中的基础故障率0.001–0.005 s⁻¹、β=0.5仍标记为探索参数。共享空间风险不能自动使该独立乘积成为相关故障下的真实联合成功概率。

任务阈值为0.9/0.99/0.999/0.9999，但当前奖励仅为负时延；阈值用于记录达标与否，没有进入当前奖励，也不是动作硬筛选。系统没有实际故障事件、重试、截止期或能耗预算。因此“时延低”不等于“满足可靠性要求”。任务R需求也未包含在当前42维观测中。

单副本的可行性本身应单独统计。例如暂不加空间风险，λ=0.001 s⁻¹、C=2×10⁹ cycles、f=4 GHz时，单节点R≈0.999500，已经达不到0.9999；加入风险场后可行集合随episode变化。高阈值下单副本失败达标并不自动证明其选择算法差，可能是任意单节点都无法满足要求。

比较单副本与双副本可以回答复制是否值得：在同一任务流、服务器参数和风险场下，让单副本方法真的只提交一个CPU作业，报告时延、可靠性阈值达标率、CPU占用与传输开销。不能在双副本接口中把同一服务器填两次来伪造单副本，也不能删除论文的能耗/期限/恢复机制后声称完整复现。若要比较相同双副本动作空间，则需将策略改写为节点对策略，并明确称为适配方法。

## A类：优先考虑的四篇故障可靠性单节点论文


### 1. RASOUL: A Reliability-Aware Task Allocation Strategy to Improve Success Rate and Energy Saving in Mobile-Edge Computing

条目键：`ETI9KJD8`。依据：本地PDF系统模型，PDF pp.4–7，式(13)–(19)及算法1。[论文书目/DOI](https://doi.org/10.1109/JIOT.2025.3592330)。

任务为独立的非周期软实时任务，含计算量、输入量、软期限及本地预处理份额；分配变量满足Σxᵢ=1。服务器可以多核，任务进入负载较低的核，区别于repo单容量队列。

CPU执行可靠性Rᵢ=exp(-λᵢc/fᵢ)，要求每任务Rᵢ≥Rreq。论文λ随归一化频率变化：λ₀·10^[ω(1-fnorm)/(1-fmin)]，并不是repo的固定基础λ加空间风险。另以MTBF/(MTBF+MTTR)描述历史可用性，以软期限分段函数描述QoS；二者估计的服务成功分数不能直接替代CPU可靠性。

算法先筛去CPU可靠性不满足要求的节点，再结合历史QoS、可用性与终端能耗评分排序，由advisory unit进行服务器利用率准入。收益为成功服务与终端能耗的加权组合，能耗包括发送及本地预处理，不应误写为完整服务器CPU能耗。原文称采用UCB1，但可用性估计式含减去置信半径的项；复现应核对式(18)及算法1，不能仅按算法名套标准UCB。

建议保留“可靠性筛选＋学习服务表现＋负载准入”结构作为首选单副本方法。repo没有能耗和期限，需补机制或明确给出删减后的RASOUL适配版；当没有可行节点时，需显式记录不可行/拒绝，不应静默改为双副本。初始化无历史观测、概率界截断等也需有定义。

### 2. Reliability-aware optimization of task offloading for UAV-assisted edge computing

条目键：`XPM57MLT`。依据：本地PDF系统模型，PDF pp.4–8，式(7)(8)(24)(29)、问题与动作定义。[论文书目/DOI](https://doi.org/10.1109/TC.2025.3604463)。

任务为不可分五元组，包括计算需求、输入量、到达时刻、来源用户和期限。离散目的地单选本地、某一UAV或边缘云；UE/UAV以CPU积压更新队列，云为固定分配计算资源且无同样队列。

CPU故障为Poisson过程，Rcpu=exp(-αC/f)；传输故障Rtx=exp(-βTtx)，边缘执行可靠性为两者乘积。论文按执行时间计算CPU生存概率，不把整个排队时间直接放入该指数。失败视为一次事件，不再影响后续任务；文中解释可修复软错误，不等于算法把同一失败任务重试作为主要决策变量。

联合动作包含离散节点和连续UAV位置、发射功率；用混合动作表示及TD3学习TRO，目标长期成功任务比例，同时处理超期丢弃和能量预算。其成功包含“按期且无故障”，比repo记录的理论概率更强。

适配时可以固定节点位置、功率和链路参数，保留单节点决策与队列；必须说明省略了轨迹控制。若继续用概率指标，应报告TRO适配后的期望成功度，不能冒称已经模拟论文中的真实失败/超期。

### 3. Quality of experience and reliability-aware task offloading and scheduling for multi-user mobile-edge computing systems

条目键：`KQ4FD48B`。依据：本地PDF系统模型，PDF pp.3–8，式(12)–(15)、分配/资源/BPSO算法。[论文书目/DOI](https://doi.org/10.1109/TSC.2025.3552338)。

每个用户任务完整地在本地或一个ES执行，ES在同一批次给多个任务分配CPU份额fᵢⱼ，满足Σᵢfᵢⱼ≤Fⱼ。属于批次资源共享，不能原样套用到repo逐到达FIFO。

卸载任务可靠性包含传输exp(-γTtx)和计算exp[-λ(f)νᵢcᵢ/fᵢⱼ]；νᵢ表示任务脆弱性。约束是系统Rsys≥Rth，Rsys为所有任务可靠性乘积。对多个任务取乘积的系统可靠性，会随任务数量下降；它不等于每个任务分别满足Rreq。

方法分三层：依据服务器/任务脆弱性索引进行可靠性感知任务分配；用Lagrange/KKT求QoE最优CPU分配；用BPSO搜索本地/卸载组合。不是只有PSO挑一个节点。

可以作为非DRL可靠性优化对照，尤其是批次/窗口调度。若对当前在线FIFO模型只保留节点排序，需要明确称为该论文分配启发式的适配版；固定f并移除CPU分配不再是原问题。

### 4. LLM-enhanced deep reinforcement learning for task offloading in collaborative edge computing

条目键：`HY4YPKGL`。依据：本地PDF系统模型，PDF pp.2–5，系统模型、可靠性约束与MAPPO策略优化。[论文书目/DOI](https://doi.org/10.1109/SECON68281.2026.11579040)。

独立原子任务最终只在一个节点执行，允许执行前经多个邻居转发。Σⱼxᵢⱼ≤1，存在本地执行、接收/执行队列和链路连接变化；“多个跳点”不代表“多个计算副本”。

单任务可靠性exp[-(αⱼ+γⱼ)Tc-βᵢⱼTt]同时考虑软件、硬件和链路故障，并受期限、CPU、内存及网络容量约束。策略状态包括故障风险、负载与当前任务等，成功或违反约束产生奖惩。

LeDRL以MAPPO为基础，用LLM生成本地/指定节点建议、上下文记忆和反思，再用注意力融合政策先验。论文提供代码地址，但本次没有运行或验证代码与论文一致性：[LeDRL代码](https://github.com/GalleyG5/LeDRL)。

适合增加一个可靠性感知PPO系方法，但完整复现成本较高。固定拓扑、去除LLM后只比较MAPPO不能命名为完整LeDRL；可作为消融或说明是无LLM适配版。repo还需给策略提供Rreq、期限和相应故障语义。

## B类：严格单节点，但可靠性目标与CPU故障不同

### CVaR-constrained reinforcement learning for ultra-reliable task offloading in LEO satellite edge computing

`M4SYZZES`；**CVaR约束PPO＋Lagrange乘子**。整任务在本地/卫星/地面云单选；MMPP突发到达、有限CPU队列、重尾任务。损失包含时延、超期与丢弃；约束episode级CVaR。不是CPU指数生存概率硬约束。

证据：本地PDF系统模型，PDF pp.2–3，MDP与CVaR约束。[来源](https://doi.org/10.1109/PRMVAI70103.2026.11605648)。

### Delay-prioritized and reliable task scheduling with long-term load balancing in computing power networks

`EJMBLZL3`；**PCTD3＋Lyapunov**。原子任务选择一个计算节点及网络路径；计算和转发均有优先级队列。可靠性主要是期限内服务，CMDP控制长期计算/网络负载均衡。需要额外路径及双优先级机制。

证据：本地PDF系统模型，PDF pp.3–4、8–9，系统/队列与PCTD3。[来源](https://doi.org/10.1109/TSC.2024.3495500)。

### Security-Sensitive Task Offloading in Integrated Satellite-Terrestrial Networks

`6J648F9U`；**PPO任务分配与顺序优化**。每任务只分配一次，单选本地或LEO，FCFS队列；可靠性/安全性涉及传输误码及攻击风险，联合任务分配和卸载顺序。不能直接替换CPU故障率。

证据：本地PDF系统模型，PDF pp.4–6，分配约束Ση≤1、通信及安全模型。[来源](https://doi.org/10.1109/TMC.2024.3489619)。

### Latency and Reliability-Aware Task Offloading and Resource Allocation for Mobile Edge Computing

`RLJPEYVV`；**EVT＋Lyapunov资源优化**。多UE/MEC队列，原子卸载任务选一台服务器，CPU与传输资源动态调度；URLLC以极端队列长度/尾时延约束定义，无CPU故障生存率。区分一批任务分流与同一任务切分。

证据：本地PDF系统模型，PDF pp.2–4，队列/卸载与EVT约束。[来源](https://doi.org/10.1109/GLOCOMW.2017.8269175)。

### Reliable Task Offloading in Sustainable Edge Computing with Imperfect Channel State Information

`HMEBHKAZ`；**ROMA（Lyapunov＋MAPPO）**。IoT任务整数单选本地或一个AP；可再生能源、NOMA及不完美CSI，可靠性是信道与能量短缺下的服务成功率，采用长期期望约束；最小化AP电网能耗。

证据：网页可访问系统模型，Section III，PDF pp.3–5；式(21)C2及Section IV。[来源](https://www.cs.newpaltz.edu/~lik/publications/Peng-Peng-IEEE-TNSM-2024)。

### To Risk or Not to Risk: Learning with Risk Quantification for IoT Task Offloading in UAVs

`U36XDGYE`；**DRQ（风险量化DRL）**。智慧农场UAV/IoT图像任务单选本地、其他UAV或MEC；队列、能量及期限限制，CVaR评估不同任务损失风险，非CPU指数故障。

证据：网页可访问系统模型，Section II System Model。[来源](https://arxiv.org/html/2302.07399v1)。

### Dynamic Task Offloading and Resource Allocation for Ultra-Reliable Low-Latency Edge Computing

`MD5KUZXP`；**EVT＋Lyapunov＋UE/MEC关联匹配**。不可再分的Aunit原子任务在本地或关联MEC处理，Ση=1；任务集合可以分流。长期/短期资源控制与极端队列尾风险，非CPU故障概率。

证据：网页可访问系统模型，Sections II–III，原子任务与单MEC关联约束。[来源](https://arxiv.org/html/1812.08076)。

### RATE: Reliability-Aware Task Service in Fog-Enabled IoV Environments

`7LYY7D66`；**RATE（Q-learning＋模拟退火）**。IoV任务选候选fog，模拟退火做请求接受与容量/收益控制；可靠性是历史实际/期望执行及等待时延形成的加权移动评分，不是故障概率。

证据：网页可访问系统模型，Section III System Model，时延历史可靠性与fog节点选择。[来源](https://www.researchgate.net/publication/378896769_RATE_Reliability-Aware_Task_Service_in_Fog-Enabled_IoV_Environments)。

### Towards Risk-Averse Edge Computing With Deep Reinforcement Learning

`3EH686AT`；**PPO-MV / PPO-DSR**。移动用户各时隙得到服务器权重向量，对每个独立任务只采样一个ES。组合分散不同任务，并不复制同一任务；以均值方差及差分Sharpe收益控制时延风险。

证据：网页可访问系统模型，Sections 3.2–3.3、5.2；作者公开全文。[来源](https://www.researchgate.net/publication/375203513_Towards_Risk-Averse_Edge_Computing_With_Deep_Reinforcement_Learning)。

风险厌恶PPO一文的组合权重是服务器选择概率：任务1和任务3可以选服务器1，任务2和任务4可以选服务器4，每个任务仍只采样一个节点。适合作为“时延波动风险”对照，不能把组合分散解释为同任务复制。ROMA控制长期可靠性期望，RATE为历史服务评分，二者均不提供与逐任务CPU生存阈值直接等价的约束。上述网页摘要均控制在各源允许的简短概括范围。

## C类：单点放置、但含故障后的额外执行

### ESFMTO: A reliable task offloading strategy based on edge server failure model in IIoT

`SIK5DA7T`；**ESFMTO（BNN＋CVaR＋SAC）**。任务选择一个ES，硬件/容器采用故障—修复模型；失败可能修复后重复执行。BNN估计完成时间分布，CVaR与SAC控制截止期风险。属于单节点放置，不等于一次执行的严格单副本。

证据：本地PDF系统模型，PDF pp.3–6，失败/修复/重执行模型与MDP。[来源](https://doi.org/10.1016/j.adhoc.2025.103887)。

### Reliability-aware task processing and offloading for data-intensive applications in edge computing

`KVZXU9ZL`；**RTPO（凸松弛＋ADMM）**。数据密集任务本地或单ES处理，联合压缩、卸载和资源分配；Poisson故障与指数修复，执行尝试次数为几何型过程。优化处理时延及可靠性/能量约束。需把恢复时间和重复CPU消耗计入。

证据：本地PDF系统模型，PDF pp.3–7，故障/修复/完成概率模型与ADMM。[来源](https://doi.org/10.1109/TNSM.2023.3258191)。

### Fault-tolerant mobile service offloading in mobile edge computing

`FJBEC772`；**Dueling DQN＋自适应checkpoint**。单节点卸载配合检查点与失败后恢复，CPU队列及故障下总完成时间；控制卸载和checkpoint频率。需要扩展repo故障事件与恢复机制。

证据：本地PDF系统模型，PDF pp.2–4，单节点放置及checkpoint模型。[来源](https://doi.org/10.1109/TASE.2025.3557934)。

### Fault tolerant & priority basis task offloading and scheduling model for IoT logistics

`T9MISUM7`；**FP-TOSM（AHP＋动态重聚类）**。IoT物流按优先级本地/fog/cloud执行，AHP选VM，失败采用动态重聚类；不属于可确认的一次单节点执行模型。

证据：网页检索后回退摘要，未取得可核读的系统模型；以下仅由摘要支持。[来源](https://doi.org/10.1016/j.aej.2024.10.018)。

这些方法可作为“复制与恢复机制”的第二组比较，前提是所有算法都计入重试/检查点CPU时间、通信及失败后完成时延，并统一故障事件流。当前repo没有这些机制，不能单纯换agent完成忠实复现。RTPO缺PDF的重复记录46CQT2SF使用同DOI的KVZXU9ZL本地PDF分析，只计一种方法。

## 建议最终选用与实验解释

第一组优先做 **RASOUL＋TRO**：一个代表可靠性筛选和在线历史学习，一个代表在线队列状态下的DRL单节点策略。再加入该QoE论文的可靠性感知分配/BPSO方法，可形成非DRL优化对照。若需要PPO系故障方法，再考虑LeDRL，复现时保留/删减的LLM与多跳机制应明示。

第二组可加入PPO-MV/PPO-DSR或卫星CVaR-PPO来比较时延风险，但明确其可靠性含义不同；ESFMTO/RTPO适合扩展了真实失败与恢复的实验。摘要候选不作为已确认单副本方法引用。

为了区分复制收益和决策收益，建议并行报告：平均及P95/P99任务时延、逐任务可靠性达标率、单节点可行集合为空的比例、理论完成概率、CPU cycles占用及传输MB；只在确实采样故障时报告实际执行成功率。所有方法用相同任务/节点/风险场种子和训练预算。若给一部分方法Rreq而另一些方法不可见，应说明信息不对等；当前reward只含时延，要另设明确的可靠性优化实验或可行性筛选实验。
