# 同时采用泊松传输故障与执行故障模型的文献

核查日期：2026-10-19。依据当前文库已提取的本地PDF系统模型逐项核对。明确符合的卸载论文有6篇；O2O-DRL有两条同DOI记录（8QVF796E、YPD2CZEK），按一篇计。另有1篇早期网格计算支撑文献。下列所有6篇均有本地可读PDF。

统一写法：Nc(t)~Poisson(λc t)，Nt(t)~Poisson(λt t)，因此Rexec=P[Nc(tc)=0]=exp(−λc tc)，Rtrans=exp(−λt tt)。在对应独立假设下，单路径R=Rexec×Rtrans。计数服从泊松分布、首次故障等待时间服从指数分布、零故障概率为指数形式，是同一模型的不同表述。但只有指数形式不足以证明作者明确采用泊松故障过程。

## O2O-DRL — Decentralized task offloading in edge computing: An offline-to-online reinforcement learning approach

- 年份：2024；Zotero键：`8QVF796E`。
- 模型定位：第III-A节，PDF第4页／出版页1606，式(3)–(5)。
- 系统与可靠性：协作边缘网络中各节点接收独立任务，选择本地或另一个节点，FIFO执行及收发队列。计算节点失效率αj、传输链路失效率βij；执行可靠性exp(−αj Tc)，传输可靠性exp(−βij Tt)。成功统计同时要求按期、执行无故障和传输无故障。
- 使用限制：单节点执行，不是任务复制。泊松过程描述故障，不是到达过程；此文到达为Bernoulli。
- 来源：[DOI出版页](https://doi.org/10.1109/TC.2024.3377912)。

## TRO — Reliability-aware optimization of task offloading for UAV-assisted edge computing

- 年份：2025；Zotero键：`XPM57MLT`。
- 模型定位：第III-C节，PDF第4–5页／出版页3835–3836，式(6)–(8)。
- 系统与可靠性：UE可本地执行或卸载至UAV/边云，任务到达触发决策，UAV FIFO队列。计算故障按速率αj的泊松过程计数，Rcomp=exp(−αj tco)；链路故障速率βmj，Rtrans=exp(−βmj ttr)。优化任务成功率并联合轨迹和资源。
- 使用限制：每任务整体选择一个执行位置；两部分都按泊松失效建立，不是有限块长误码模型。正文主要针对soft errors，并讨论用失效率调整反映硬件离线。
- 来源：[DOI出版页](https://doi.org/10.1109/TC.2025.3604463)。

## HRTO — Hybrid redundancy for reliable task offloading in collaborative edge computing

- 年份：2025；Zotero键：`WV7TGTXZ`。
- 模型定位：第III-A节，PDF第4页／出版页3241，式(3)–(5)。
- 系统与可靠性：协作边缘集群、邻接节点转发、FIFO队列，完整独立任务。执行故障速率αj，Rcomp=exp(−αj Tc)；链路故障速率βij，Rtrans=exp(−βij Tt)。主动复制与失败后再执行结合。
- 使用限制：六篇中优先用于研究复制；集群内部实例数、失败后重试及首成功取消规则会影响能耗和队列。
- 来源：[DOI出版页](https://doi.org/10.1109/TC.2025.3587620)。

## LeDRL — LLM-enhanced deep reinforcement learning for task offloading in collaborative edge computing

- 年份：2026；Zotero键：`HY4YPKGL`。
- 模型定位：第III-A/B节，PDF第3页／出版页235，式(3)、(4)、(6)。
- 系统与可靠性：协作边缘网络同时区分执行软件故障αj、节点硬件故障γj、无线传输故障βij，三者明确建模为泊松过程。总可靠性Ri=exp[−(αj+γj)Tc−βijTt]≥Φi，另约束端到端期限及资源。
- 使用限制：每任务最多一个执行节点；βij为有限次重传机制之后的有效链路失效率，不是原始BER；总可靠性指数不计等待时间，等待仍进入期限约束。
- 来源：[DOI出版页](https://doi.org/10.1109/SECON68281.2026.11579040)。

## ReLIEF — ReLIEF: A reinforcement-learning-based real-time task assignment strategy in emerging fault-tolerant fog computing

- 年份：2023；Zotero键：`YNX4H396`。
- 模型定位：第III-C节，PDF第5页，式(7)–(9)。
- 系统与可靠性：fog broker为不可分实时任务选主备节点，文中明确节点和通信链路故障均受泊松过程影响，计算与链路各有失效率，单路径可靠性为两部分乘积。
- 使用限制：主备容错，备份不等同同时执行。正文式(8)/(9)存在排版/符号不一致，复现时应按传输时长、bit/s与失败率单位检查，不能盲目照搬提取文本。
- 来源：[DOI出版页](https://doi.org/10.1109/JIOT.2023.3240007)。

## FT-DSAC — Fault-Tolerant Aware Task Offloading Based on Reinforcement Learning in Mobile Edge Computing

- 年份：2025（作者版）；Zotero键：`KX9FH3L7`。
- 模型定位：第III-B.5节，PDF第5页，式(6)、(7)。
- 系统与可靠性：DAG子任务在ES上执行，边层网络设备/链路承担依赖数据传输。执行故障率η1(s)、传输链路故障率η2(s,s′)，对应Rexec=exp(−η1 CD)、Rtrans=exp(−η2 TD)。主备调度兼顾子网位置及启动时序。
- 使用限制：DAG依赖边传输，不只是终端上传；备用在故障后启用，跨子网约束用于隔离网络设备故障。
- 来源：[DOI出版页](https://doi.org/10.1109/TMC.2025.3636100)。

## 延伸参考与严格排除

**Optimal task partition and distribution in grid service system with common cause failures（2007，J8GUFM2K）**：本地PDF第3页模型假设(5)明确资源与通信链路故障到达均为泊松过程；不同基本资源/链路故障独立，但多个执行资源可共享通信通道，从而对任务结果形成共同失效影响。任务可拆分，同一子任务可分配多个资源，取首个返回结果；总体任务要等全部子任务结果。故障暴露区间可延伸至结果返回，不能一概改成仅CPU计算时长。[出版页](https://doi.org/10.1016/j.future.2006.05.002)。

**Quality of experience and reliability-aware task offloading and scheduling for multi-user mobile-edge computing systems（KQ4FD48B）**：本地PDF第4页第III-D节式(6)–(9)，传输与执行均使用指数可靠性并相乘，但正文称传输为bit-error model、执行为exponential model，本次没有找到明确的Poisson表述。因此是数学形式相近的补充，不列入上述6篇严格确认项。

**TORE-NET、RASOUL**：本轮未确认传输部分同时建立独立泊松故障模型，不能仅凭计算可靠性指数模型纳入。

**5G mMTC、NOMA URLLC及卫星纠错类**：传输可靠性可能来自有限块长、误码率、链路中断或期限违约，也不能据“可靠传输”推定泊松失效。

如果研究的是同任务复制，优先看HRTO；如果需要最直接的执行/传输双指数模型，优先看O2O-DRL和TRO；如果还需要明确的总可靠性硬门槛，LeDRL的式(6)最清楚；若研究主备及故障域隔离，再看ReLIEF与FT-DSAC。
